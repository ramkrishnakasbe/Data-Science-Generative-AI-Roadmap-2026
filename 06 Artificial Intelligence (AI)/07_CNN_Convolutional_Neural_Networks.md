# Convolutional Neural Networks (CNN)

CNNs are neural networks designed primarily for **image and spatial data**.

They automatically learn hierarchical features such as:

```text
Edges
  ↓
Textures
  ↓
Shapes
  ↓
Parts
  ↓
Objects
```

Common applications:

* Image Classification
* Object Detection
* Image Segmentation
* Face Recognition
* Medical Imaging
* OCR
* Image Similarity
* Video Analysis

---

# 1. Why CNNs?

A fully connected neural network is inefficient for images because an image can contain thousands or millions of pixels.

For example:

```text
224 × 224 × 3
```

contains:

```text
150,528 input values
```

A fully connected architecture would require a very large number of parameters.

CNNs solve this using:

```text
Local Connectivity
+
Weight Sharing
+
Hierarchical Feature Learning
```

---

# 2. CNN Basic Architecture

A typical CNN:

```text
Input Image
     ↓
Convolution
     ↓
Activation
     ↓
Pooling
     ↓
Convolution
     ↓
Activation
     ↓
Pooling
     ↓
Flatten / Global Pooling
     ↓
Fully Connected Layer
     ↓
Output
```

Modern architectures may replace the final flattening/fully connected structure with global average pooling or other heads.

---

# 3. Image Representation

A color image is generally represented as:

```text
Height × Width × Channels
```

Example:

```text
224 × 224 × 3
```

where:

```text
224 → Height
224 → Width
3   → RGB Channels
```

For grayscale:

```text
224 × 224 × 1
```

---

# 4. Convolution

Convolution applies a small learnable filter, also called a kernel, across the input.

Conceptually:

```text
Input
┌───────────────┐
│               │
│       ███     │
│       ███     │
│       ███     │
│               │
└───────────────┘
        ↓
     Kernel
        ↓
Feature Map
```

The kernel slides across the image and computes local weighted combinations.

---

# 5. Kernel / Filter

A kernel is a small matrix of learnable parameters.

Example:

```text
[ w1  w2  w3 ]
[ w4  w5  w6 ]
[ w7  w8  w9 ]
```

The same kernel is applied across different spatial locations.

This is called:

```text
Weight Sharing
```

---

# 6. Convolution Operation

For a simple 2D convolution, the output is generated by multiplying corresponding input values and kernel weights and summing them.

Conceptually:

```text
Input Patch
    ×
Kernel
    ↓
Weighted Sum
    ↓
Output Pixel
```

A bias can then be added.

---

# 7. Feature Map

The output produced by a convolution filter is called a **feature map** or activation map.

```text
Input Image
      ↓
Filter 1 → Feature Map 1
Filter 2 → Feature Map 2
Filter 3 → Feature Map 3
```

Different filters can learn different patterns.

For example:

```text
Filter 1 → Horizontal Edges
Filter 2 → Vertical Edges
Filter 3 → Curves
Filter 4 → Textures
```

---

# 8. Low-Level to High-Level Features

CNN layers learn increasingly complex representations.

```text
Early Layers
→ Edges
→ Corners
→ Textures

Middle Layers
→ Shapes
→ Object Parts

Deep Layers
→ Semantic Patterns
→ Objects
```

This hierarchical representation is one of the key strengths of CNNs.

---

# 9. Stride

Stride determines how far the kernel moves after each operation.

### Stride = 1

```text
Move:
→ 1 pixel at a time
```

### Stride = 2

```text
Move:
→ 2 pixels at a time
```

Increasing stride generally reduces the spatial dimensions.

---

# 10. Padding

Padding adds extra values around the input, commonly zeros.

Example:

```text
Without Padding

[ x x x ]
[ x x x ]
[ x x x ]


With Padding

[ 0 0 0 0 0 ]
[ 0 x x x 0 ]
[ 0 x x x 0 ]
[ 0 x x x 0 ]
[ 0 0 0 0 0 ]
```

Padding helps control output dimensions and allows edge information to participate more fully.

---

# 11. Valid Padding

With:

```text
padding = 0
```

no padding is added.

This is commonly called:

```text
Valid Convolution
```

Spatial dimensions usually decrease when the kernel is larger than 1 and stride is 1.

---

# 12. Same Padding

"Same" padding is commonly used to maintain spatial dimensions when:

```text
stride = 1
```

For example:

```text
Input:
32 × 32

Kernel:
3 × 3

Stride:
1

Same Padding:

Output:
32 × 32
```

---

# 13. Output Size Formula

For one spatial dimension:

```text
Output Size =
floor((N + 2P - K) / S) + 1
```

Where:

```text
N = Input Size
P = Padding
K = Kernel Size
S = Stride
```

For height and width, apply the formula independently.

---

# 14. Example of Output Size

Input:

```text
32 × 32
```

Kernel:

```text
3 × 3
```

Stride:

```text
1
```

Padding:

```text
1
```

Then:

```text
Output =
floor((32 + 2(1) - 3) / 1) + 1

= 32
```

Output:

```text
32 × 32
```

---

# 15. Number of Filters

Suppose:

```text
Input:
32 × 32 × 3
```

and convolution uses:

```text
64 filters
```

The output channels become:

```text
64
```

Therefore, with suitable padding and stride:

```text
Output:
32 × 32 × 64
```

---

# 16. Number of Parameters in Convolution

For a standard convolution:

```text
Parameters =
Kernel Height
× Kernel Width
× Input Channels
× Number of Filters
+
Biases
```

Example:

```text
Kernel = 3 × 3
Input Channels = 3
Filters = 64
```

Weights:

```text
3 × 3 × 3 × 64 = 1,728
```

Biases:

```text
64
```

Total:

```text
1,792
```

---

# 17. Why CNNs Have Fewer Parameters

A fully connected layer connects every input to every neuron.

CNNs instead use:

```text
Local Connections
+
Shared Kernel Weights
```

Therefore, the same filter can detect a pattern anywhere in the image.

This greatly reduces parameter count.

---

# 18. Translation Equivariance

A key property of convolution is approximate **translation equivariance**.

If an object shifts spatially:

```text
Object Position A
      ↓
Feature Position A

Object Position B
      ↓
Feature Position B
```

The same filter can detect the same local pattern at different positions.

This is different from strict translation invariance.

---

# 19. Convolution vs Fully Connected Layer

| Feature           | Convolution | Fully Connected   |
| ----------------- | ----------- | ----------------- |
| Connectivity      | Local       | Global            |
| Weight Sharing    | Yes         | No                |
| Spatial Structure | Preserved   | Usually flattened |
| Parameters        | Lower       | Higher            |
| Image Tasks       | Excellent   | Less efficient    |

---

# 20. Activation After Convolution

A nonlinear activation is commonly applied after convolution.

Typical pattern:

```text
Convolution
    ↓
Activation
```

For example:

```text
Conv2D
  ↓
ReLU
```

This allows the network to learn nonlinear representations.

---

# 21. Pooling

Pooling reduces spatial dimensions.

Common types:

```text
Max Pooling
Average Pooling
```

Pooling can provide:

* Reduced computation
* Reduced spatial dimensions
* Some degree of local translation robustness

---

# 22. Max Pooling

Max pooling selects the maximum value from each local region.

Example:

```text
[1  5]
[2  3]
```

Output:

```text
5
```

A common configuration:

```text
2 × 2 Pool
Stride = 2
```

reduces spatial dimensions approximately by half.

---

# 23. Average Pooling

Average pooling calculates the average value of a region.

Example:

```text
[1  5]
[2  3]
```

Average:

```text
(1 + 5 + 2 + 3) / 4
= 2.75
```

---

# 24. Max Pooling vs Average Pooling

| Feature                 | Max Pooling              | Average Pooling    |
| ----------------------- | ------------------------ | ------------------ |
| Operation               | Maximum                  | Average            |
| Emphasis                | Strongest activation     | Overall activation |
| Common Historical Usage | High                     | Moderate           |
| Information             | Keeps strongest response | Smooths responses  |

---

# 25. Global Average Pooling

Global Average Pooling averages each feature map over its entire spatial dimensions.

For:

```text
7 × 7 × 512
```

Global Average Pooling produces:

```text
1 × 1 × 512
```

It can replace a large flattening + fully connected layer.

Advantages:

* Fewer parameters
* Lower overfitting risk
* Simple classification head
* Common in modern CNN architectures

---

# 26. Flattening

Flatten converts a multi-dimensional tensor into a vector.

Example:

```text
7 × 7 × 512
```

becomes:

```text
25,088
```

This vector can be passed to a fully connected layer.

However, modern architectures often prefer global pooling to reduce parameter count.

---

# 27. Receptive Field

The **receptive field** is the region of the original input that influences a particular feature.

Early layer:

```text
Small Receptive Field
```

Deeper layer:

```text
Larger Receptive Field
```

Conceptually:

```text
Input
┌──────────────────┐
│                  │
│   ┌──────┐       │
│   │ RF   │       │
│   └──────┘       │
│                  │
└──────────────────┘
```

Deep layers can therefore capture larger structures.

---

# 28. Effective Receptive Field

The theoretical receptive field grows as layers are stacked.

Example:

```text
3 × 3 Conv
   ↓
3 × 3 Conv
   ↓
2 × 2 Pool
```

The deeper feature can depend on a larger portion of the original image.

Stride and pooling accelerate receptive-field growth.

# 32. VGG

VGG emphasized a simple architecture using repeated:

```text
3 × 3 Convolutions
```

Typical pattern:

```text
Conv 3×3
Conv 3×3
Pool
↓
Conv 3×3
Conv 3×3

```

Advantages:

* Simple architecture
* Easy to understand
* Strong feature hierarchy

Disadvantage:

```text
Very Large Parameter Count
```

---

# 33. VGG Insight

Several small convolutions can replace a larger convolution while introducing additional nonlinearities.

For example:

```text
3 × 3
+
3 × 3
```

provides a larger effective receptive field while using nonlinear transformations between layers.

This became an important architectural design idea.

---

# 34. GoogLeNet / Inception

Inception introduced the idea of applying multiple operations in parallel.

Conceptually:

```text
              Input
                │
      ┌─────────┼─────────┐
      ↓         ↓         ↓
    1×1       3×3       5×5
     Conv      Conv      Conv
      ↓         ↓         ↓
      └─────────┼─────────┘
                ↓
           Concatenate
```

The Inception architecture also used `1 × 1` convolutions for dimensionality reduction.

---

# 35. 1 × 1 Convolution

A `1 × 1` convolution operates across channels at each spatial position.

It can be used for:

```text
Channel Reduction
Channel Expansion
Feature Mixing
Computational Efficiency
```

Example:

```text
56 × 56 × 256
        ↓
1 × 1 Conv
        ↓
56 × 56 × 64
```

Spatial dimensions remain the same if stride and padding are chosen appropriately.

---

# 36. ResNet

ResNet introduced **residual connections** to make very deep networks easier to optimize.

Instead of learning:

```text
H(x)
```

a residual block learns:

```text
F(x) = H(x) - x
```

Then:

```text
H(x) = F(x) + x
```

---

# 37. Residual Connection

Conceptually:

```text
          ┌───────────────┐
          │               │
x ───────→│ Conv → Conv   │
│         │               │
│         └───────┬───────┘
│                 ↓
└──────────────→ Add
                  ↓
                Output
```

The original input is added directly to the transformed representation.

---

# 38. Why ResNet Helps

Very deep networks can become difficult to optimize.

Residual connections provide an easier path for information and gradients.

```text
Without Residual
→ Deep Network
→ Optimization Difficulty

With Residual
→ Shortcut Connections
→ Easier Optimization
```

This enabled successful training of much deeper CNNs.

---

# 39. ResNet Variants


---

# 40. Bottleneck Block

A bottleneck block commonly uses:

```text
1 × 1
 ↓
3 × 3
 ↓
1 × 1
```

The first `1 × 1` convolution reduces channels.

The `3 × 3` convolution performs spatial processing.

The final `1 × 1` convolution expands channels.

```text
High Channels
     ↓
1×1 Reduce
     ↓
3×3 Process
     ↓
1×1 Expand
     ↓
High Channels
```

---

# 41. DenseNet

DenseNet connects each layer to many previous layers.

Conceptually:

```text
x₀
 ↓
Layer 1
 ↓
x₀ + x₁
 ↓
Layer 2
 ↓
x₀ + x₁ + x₂
 ↓
Layer 3
```

Each layer receives feature maps from previous layers.

Advantages:

* Strong feature reuse
* Improved gradient flow
* Can require fewer parameters than some comparable architectures

---

# 42. MobileNet

MobileNet was designed for efficient deployment on mobile and edge devices.

It uses **depthwise separable convolutions**.

```text
Standard Convolution
        ↓
Depthwise Convolution
        ↓
Pointwise 1×1 Convolution
```

This significantly reduces computation.

---

# 43. Standard vs Depthwise Separable Convolution

Standard convolution simultaneously performs:

```text
Spatial Filtering
+
Channel Mixing
```

Depthwise separable convolution separates these:

```text
Depthwise
→ Spatial Filtering

Pointwise 1×1
→ Channel Mixing
```

This is computationally efficient.

---

# 44. EfficientNet

EfficientNet introduced systematic model scaling across:

```text
Depth
Width
Input Resolution
```

Instead of increasing only one dimension, it uses **compound scaling**.

Conceptually:

```text
Model Scaling
      ↓
Depth + Width + Resolution
      ↓
Balanced Architecture
```

# 46. Transfer Learning

Transfer learning uses a model pretrained on a large dataset and adapts it to a new task.

```text
Pretrained CNN
      ↓
Learned Visual Features
      ↓
New Dataset
      ↓
Fine-Tuning
      ↓
Target Task
```

Example:

```text
ImageNet Pretrained Model
        ↓
Medical Image Classification
```

---

# 47. Feature Extraction vs Fine-Tuning

### Feature Extraction

Freeze most or all pretrained layers.

```text
Pretrained CNN
     ↓
Freeze Backbone
     ↓
Train New Head
```

### Fine-Tuning

Allow some or all pretrained layers to update.

```text
Pretrained CNN
     ↓
Unfreeze Selected Layers
     ↓
Train with Small Learning Rate
```

---

# 48. When to Use Transfer Learning

Transfer learning is particularly useful when:

```text
Target Dataset is Small
+
Pretrained Model is Relevant
```

Benefits:

* Faster training
* Better performance with limited data
* Less data required
* Strong pretrained representations

Two major types:

```text

```


### Instance Segmentation

Different objects of the same class are separated.

```text
Person 1

Person 3
```

# 53. CNN Limitations

CNNs are powerful but have limitations.

### Limited Global Context

A convolution starts with local receptive fields.

Very deep networks are needed to capture broad context.

### Computational Cost

Large CNNs can require significant:

```text
GPU Memory
Compute
Inference Time
```

### Long-Range Relationships

CNNs do not naturally model global relationships as directly as attention-based architectures.

This limitation contributed to the rise of Vision Transformers.

# 57. Computational Considerations

For a standard convolution, computation increases with:

```text
Input Height
× Input Width
× Kernel Height
× Kernel Width
× Input Channels
× Output Channels
```

Therefore, reducing channels or using efficient convolution operations can substantially reduce computation.

---

# 58. Depthwise Separable Convolution

For input:

```text
H × W × C
```

with kernel:

```text
K × K
```

standard convolution cost is roughly proportional to:

```text
H × W × K × K × C × C_out
```

Depthwise separable convolution separates this into:

```text
Depthwise:
H × W × K × K × C
```

plus:

```text
Pointwise:
H × W × C × C_out
```

This can significantly reduce computation.

# 61. Mixup

Mixup creates virtual training examples by combining two examples.

Conceptually:

```text
Image A + Image B
       ↓
Mixed Image
```

Labels are also mixed according to the mixing coefficient.

It can improve generalization and reduce overconfidence.

---

# 62. CutMix

CutMix replaces a region of one image with a region from another image.

```text
Image A
┌─────────────┐
│             │
│    Image B  │
│    Region   │
│             │
└─────────────┘
```

The label is adjusted according to the area contributed by each image.

# 64. Intersection over Union

IoU measures overlap between predicted and ground-truth regions.

```text
IoU =
Intersection / Union
```

Conceptually:

```text
             Prediction
          ┌─────────────┐
          │     ┌───────┼──┐
          │     │Overlap│  │
          └─────┼───────┘  │
                └───────────┘
```

Higher IoU means better overlap.

---

# 65. Non-Maximum Suppression

NMS is commonly used in object detection.

Problem:

```text
One Object
   ↓
Multiple Bounding Boxes
```

NMS:

```text
Keep Best Box
      ↓
Remove Highly Overlapping Boxes
```

Basic process:

```text
1. Select highest-confidence box
2. Calculate IoU with other boxes
3. Remove boxes above threshold
4. Repeat
```
